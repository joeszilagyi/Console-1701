# ORBITAL CelesTrak ISS GP Fixture

Checked 2026-10-15 against CelesTrak's [GP format documentation](https://celestrak.org/NORAD/documentation/gp-data-formats.php) and [usage policy](https://celestrak.org/usage-policy.php). The documented single-object `CATNR=25544&FORMAT=JSON` query returned HTTP 200, 422 bytes, and one ISS record with OMM-style fields. Its public identity was `ISS (ZARYA)`, catalog 25544, international designation `1998-067A`, classification `U`, and a UTC GP epoch. CelesTrak says GP updates occur about once every two hours and warns against repeated downloads within one update cycle. No app polling was added.

The fixture intentionally includes several orbital elements to prove that the parser drops them. Only the fixed ISS identity, source URL, and epoch are retained. The item is background catalog-freshness context; it provides no live position, pass time, trajectory, maneuver, or conjunction estimate. Parser input is capped at one record and rejects every other catalog ID, malformed identity, or invalid epoch. The new `celestrak_iss_gp` registry row stays disabled and has no live HTTP allowlist entry. The original broad `celestrak_elements` candidate remains sensitivity-blocked before fixture access; SATCAT, supplemental GP, and SOCRATES remain disabled.

Before any live admission, retain the one-object URL, require at least a two-hour interval and backoff, verify response-size and cache behavior, and confirm the display is still catalog-freshness only. Detailed SATCAT, supplemental GP, and SOCRATES risk reviews remain separate.
