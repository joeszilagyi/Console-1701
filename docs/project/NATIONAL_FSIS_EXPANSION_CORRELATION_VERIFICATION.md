# FSIS expansion correlation verification

On 2026-10-15, exact-number research requests to the [FSIS recall API](https://www.fsis.usda.gov/fsis/api/recall/v/1) returned an English original recall `005-2026` and an English expansion `005-2026-EXP`. The [original query](https://www.fsis.usda.gov/fsis/api/recall/v/1?field_recall_number=005-2026) identified Ajinomoto Foods North America chicken fried rice products with recall date 2026-02-19. The [expansion query](https://www.fsis.usda.gov/fsis/api/recall/v/1?field_recall_number=005-2026-EXP) identified the same company and an expanded chicken and pork fried rice, ramen and shu mai product scope with recall date 2026-03-03. Each had its own FSIS notice URL and full recall number. Later repeat requests received HTTP 403, so this slice uses the previously observed fields and an offline test adaptation of the existing checked-in FSIS fixture; it does not claim a fresh full-payload capture.

The matcher accepts the lineage only when both items have official FSIS source metadata, parser-backed recall numbers match the numeric original plus exact `-EXP` suffix, and each item has only its own FSIS identifier. Conflicting IDs in any other namespace still veto the match. Both full notice IDs and URLs remain separate in stored item evidence; the cluster match basis is `same_fsis_recall_series`. One FSIS family gives no independent corroboration. Different recall numbers, an extra FSIS identifier, and a non-FSIS source family do not use this exception.

The fixture parser and source remain fixture-only. This match does not establish the original notice's current status, the expansion's changed products for any other series, or a live FSIS fetch policy. Exact API discovery, bounded response size and live cadence remain separate gates.
