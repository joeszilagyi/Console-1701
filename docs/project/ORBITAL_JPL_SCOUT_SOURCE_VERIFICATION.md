# ORBITAL JPL Scout Source Verification

Checked 2026-10-15 against NASA/JPL's [Scout API documentation](https://ssd-api.jpl.nasa.gov/doc/scout.html) and [SSD API fair-use policy](https://ssd-api.jpl.nasa.gov/doc/index.php). A single researcher read of the documented summary endpoint returned HTTP 200, 34,191 bytes, 92 records, and signature `NASA/JPL Scout API` version `1.3`. This is a changing near-real-time NEOCP candidate set, not a stable list of confirmed Earth impacts.

The documented no-parameter summary mode has a `count` and key/value `data` records. The fixture preserves two observed row shapes plus an invalid designation. The parser accepts only the registered ORBITAL Scout identity, exact version/source signature, a matching count of at most 200, valid provisional designations, positive observation count, and parseable `lastRun` format. It stores the source's last-run string without assigning a timezone because the summary documentation does not state one. It omits `neoScore`, `phaScore`, `caDist`, and other risk/geometry values from the stored item. Every resulting item is background class and explicitly says it does not establish an impact prediction. The object URL uses JPL's documented `tdes` detail query; the app does not fetch it.

The official policy asks clients to make only necessary serial requests, cache, back off on errors, identify the client with a product/version/contact User-Agent, and check API versions. The registry source remains disabled and fixture-only. Before any live admission, verify a bounded response-size strategy, update cadence and expiry behavior, rate-limit handling, source time semantics, and an application-specific User-Agent; then add an exact disabled-by-default HTTP contract and live smoke evidence. Sentry remains separately unverified.
