# FSIS Recall API fixture verification

Reviewed 2026-10-15 for RS-034 and RS-041. [FSIS's Recall API page](https://www.fsis.usda.gov/science-data/developer-resources/recall-api) publishes a JSON GET service at `https://www.fsis.usda.gov/fsis/api/recall/v/1`. Earlier bounded requests from this machine returned HTTP 403. A later bounded review returned HTTP 200 `application/json`: the unfiltered response was 12,996,284 decoded bytes and 2,030 rows. That is too large for this app's ordinary live fetch cap, and the API remains outside the live HTTP allowlist.

A direct `field_recall_number=029-2024` GET returned a 13,481-byte JSON array with English and Spanish rows for one recall. Exact-number queries for `001-2026`, `002-2026`, `PHA-10062026-01`, `025-2026`, and `019-020-2026` returned bounded JSON arrays. Observed fields include recall number/export number, title, `field_recall_url`, date, last modified date, class/risk, reason, product items, establishment, state labels, notice/archive flags, recall type, language, and HTML summary/contact fields. List-valued product, reason, establishment and state fields differ from the older example reproduced in a [2025 Japanese government report](https://www.fsc.go.jp/fsciis/attachedFile/download?fileId=003&retrievalId=cho20250050001). The API emits `http://www.fsis.usda.gov/recalls-alerts/...` notice links; a bounded HEAD of the corresponding HTTPS `001-2026` page returned HTTP 200.

The API's `field_active_notice` flag is **not** equivalent to an active recall. In the observed 2026 rows, nine records marked `Active Recall` had that flag `False`; one `Closed Recall` had both `field_active_notice=True` and `field_archive_recall=True`. The parser preserves these raw fields, records contradictory lifecycle combinations, and derives current attention from `Active Recall` with no archive flag or from a current flagged Public Health Alert. A closed Class I record is retained as evidence without a current high-risk attention claim. The observed response also includes `Public Health Alert` risk/class values, Spanish translations, duplicate state labels, and combined recall number `019-020-2026`; the parser handles those cases.

A bounded review of the unfiltered response found 42 English 2026 rows. Their reduced JSON metadata was 222,367 bytes and all 42 parsed offline through the fixture parser. One expansion number, `005-2026-EXP`, required a distinct accepted identity form. This review checked schema tolerance; it did not approve the unfiltered response for app fetching.

`fsis_recalls_json` accepts only an explicitly enabled local fixture under the exact registered NATIONAL FSIS identity. It caps the payload at 256 KiB and 50 rows, keeps the English record, validates stable identity and official notice URL, and stores bounded product, establishment, reason, status, date and distribution labels. It upgrades the API's official HTTP notice URL to HTTPS, preserving a consumer notice link while explicitly stating that instruction content was not parsed. It discards HTML summary and contact text before SQLite storage. State labels represent source-listed distribution, not confirmed consumption or multi-state impact. Source-stated current Class I recalls and current flagged Public Health Alerts receive NATIONAL attention through the existing policy path.

The checked-in local fixture is a reduced copy of observed 2026 API metadata with only a synthetic summary/contact canary for the discard test. Offline scans trap HTTP and preserve separate recall identities. The registry source remains disabled and outside `official_http.py`; no 13 MB unfiltered live fetch can run through the app. RS-041's fixture-first parser acceptance is complete. A later live admission requires an exact bounded discovery query, cadence and update-window policy, full response-size review, and separate signoff.
