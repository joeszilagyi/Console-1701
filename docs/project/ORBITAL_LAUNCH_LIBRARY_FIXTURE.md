# ORBITAL Launch Library 2 Fixture

Checked 2026-10-15 against [The Space Devs API documentation](https://ll.thespacedevs.com/docs) and the documented development endpoint. Version 2.3.0 is supported; the unauthenticated production limit is 15 requests per hour. The development API uses stale, limited data and is intended for testing. One sequential read of each `launches/upcoming` and `events/upcoming` endpoint returned HTTP 200, respectively 17,834 and 5,993 bytes with two result rows each. The observed envelopes include `count`, `next`, and `results`; the parser uses only the bounded `results` array.

The launch fixture retains one observed launch's UUID, current status, NET/window, last-update time, provider, vehicle, mission name, and pad. It deliberately excludes mission description, images, and embedded media. The event fixture retains a docking ID/time and a NASA webcast URL, and suppresses an observed routine press event. The parser constructs versioned detail URLs from IDs, requires timezone-aware source times, caps rows at 20, and stores current status with an explicit no-transition-history basis. Every item is background class until a responsible agency or provider supplies an independent operational update; no convergence or endorsement is inferred.

Both sources remain disabled and no Launch Library HTTP endpoint is live allowlisted. Live admission needs a 15-per-hour compliant cadence/backoff, response-size cap, expiry and status-change handling, source-health tests, and no-page-load-fetch regression. Development API rows cannot prove the current production launch schedule.

The RS-104 correlation follow-up uses the exact Launch Library UUID and source NET for a bounded 96-hour join with linked Spaceflight News metadata when the launch record's `last_updated` is older. The linked aggregator is context only and does not create independent corroboration. A combined offline scan verifies the persisted match and a distant-publication negative case.
